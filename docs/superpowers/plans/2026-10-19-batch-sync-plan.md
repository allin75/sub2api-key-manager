# 实施与发布计划

1. 核实 Git/NAS 实际版本、原配置/卷与发布脚本；记录已批准的设计。
2. 在上游模块实现共享列表缓存、请求节流、增量明细分页和持久化全局 429 冷却；为边界补纯函数和接口测试。
3. 管理器改为列表关联筛选、统一整点调度、增量基线与定期核对；保存配额移除整批同步；补预算/权限/失败路径回归。
4. 页面增加配额等待/防重复与明确结果、限流下一次尝试时间；假数据验证桌面/手机和旧响应隔离，保存截图。
5. 全量测试、逐文件语法和差异检查；更新版本/变更说明/交接记录，提交推送已验证源码。
6. 通过 SSH 构建候选、备份源码配置与一致性数据，只替换 key-manager；验证健康、资源、隔离和业务设置保留、其他容器未变，失败回退。
7. 补记实际发布提交、备份路径、验证结果并推送 GitHub。
