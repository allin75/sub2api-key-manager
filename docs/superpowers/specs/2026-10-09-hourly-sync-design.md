# 每小时错峰同步与刷新反馈

## 用户需求

正常同步统一每小时，取消工作时段和 95% 用量触发的五分钟正常查询；分卡片错峰，减少请求。页面提供真实刷新状态、仅刷新按钮上的从左到右过渡动画，最后成功更新时间使用“数据刷新于”。记录同步失败与恢复的具体时间及错误信息。

## 推荐范围

管理员卡片为调度单元：第一位每小时 :00，第二位 :10，第三位 :20；每次只查询该管理员关联的 API Key。手动刷新只更新当前选中的管理员，不触发其他管理员。网页读缓存不访问上游。

保留夜间暂停作为推荐时段；月初、周重置、奖励到期以及未完成的状态变更仍执行原有必要操作及重试。它们与每小时正常数据查询区分。手动重复刷新继续合并，并保留最短五分钟请求间隔。

超过六位管理员时，一小时内均匀错开，避免同时查询；十分钟间隔适用于六位及以内。调度不得因服务重启而让所有卡片集中刷新，应从各自时隙恢复。

## 目标 Key 查询

保存已验证的 Sub2API Key ID，后续用 GET /api/v1/keys/:id 读取目标 Key 元信息，再读取该 Key 的每日用量。首次添加及旧数据缺少 ID 时进行一次匹配查询。校验返回 ID / 哈希与已有归属一致；错误时保留缓存，不无条件回退到整表扫描。奖励与体验账本必要的历史记录、停用恢复记录仍按原有归属处理，不丢弃已移除 Key 的历史消费。

## 页面反馈

缓存加载与实际上游同步状态分开。页面可见时读取当前管理员的轻量同步状态，后台正在刷新也显示“正在刷新数据…”。手动点击立即显示反馈，刷新按钮禁用并播放按钮内从左到右的循环过渡；不会将缓存读取误报为上游同步。遵守减少动画偏好，结束、失败、切换管理员或退出时清理动画。

显示“数据刷新于：最后成功时间”；失败不修改这个时间。另显示下一次同步时间和简洁错误状态。历史记录使用可展开的“同步记录”，无需新增独立管理页。

## 记录与隔离
