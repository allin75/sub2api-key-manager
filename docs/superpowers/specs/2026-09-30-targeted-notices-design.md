# 管理员卡片定向公告

用户已确认轻量方案，先提供本地假数据预览，不部署 NAS。

## 交互与边界

- 超级管理员在每张登录管理员卡片上点击“发布公告”，弹窗内填写标题、正文，仅发给该卡片对应账号，不增加接收人勾选或独立管理页面。
- 同一弹窗下方列出该账号的历史公告，显示发布时间和“待确认 / 已知晓”；超级管理员可二次确认后删除，接收人没有删除权限。
- 接收人登录后看到未确认公告的强提醒，多条逐一确认；确认后保留在顶部公告入口内的记录列表，直到超级管理员删除。
- 已登录的接收人通过轻量轮询（15 秒）和页面恢复可见时同步新公告；不增加 WebSocket 或第三方通知服务。
- 现有额度规则与其确认记录保持兼容，作为独立规则说明保留；定向公告仅对目标账号可见，不影响其他管理员或超级管理员自己的公告入口。
- 继续复用现有收缩、图标淡入、滚动条占位和减少动画设置；退出、会话变更、公告被删除时清理旧界面和异步操作。
- 正文为纯文本，保留换行，不允许执行 HTML。公告不自动过期，不提供修改、批量发布、全局公告管理或复杂状态统计。

## 存储与权限

- 根状态新增可选 `targetedNotices` 数组，记录稳定公告 ID、接收账号 ID、标题、正文、发布时间及确认时间。旧数据不需要破坏性迁移。
- 发布、读取账号历史和删除仅限超级管理员；普通管理员只能读取并确认属于自己的公告，忽略查询参数中的管理范围。
- 所有写入沿用 CSRF、来源校验及独占队列；确认幂等，删除与确认并发时重新检查记录是否存在。更换登录密钥不改变公告归属。

## 实施顺序与验收

1. 在 `src/announcement.js` 增加纯输入/记录校验，在 `src/store.js` 校验持久化格式，`src/server.js` 增加定向公告接口。
2. 增加管理员卡片按钮和发布/历史弹窗，顶部公告入口支持个人公告列表及逐条确认。
3. 覆盖发布/删除权限、账号隔离、并发确认、输入校验、重命名、重启、作用域预算写入和异步界面清理。
4. 本地假数据验证桌面/手机发布、实时接收、历史查看、删除及动画，保留预览给用户；更新交接记录并同步代码，NAS 保持当前部署。
