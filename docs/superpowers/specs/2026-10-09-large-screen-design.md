# 2K / 4K 页面适配方案

状态：用户已于 2026-10-09 确认按推荐方案实施。

## 目标与范围

现有内容区最大宽度 1240px，文字多为 10–14px。改善 2560×1440、3840×2160 浏览器全屏下内容偏窄、阅读尺寸偏小的问题；以 CSS 视口宽度判断，不根据设备物理分辨率或像素密度判断。

## 推荐方案

- 1920px 及以下沿用现有布局。
- 大于 1920px 后逐步增加内容区宽度、文字、内边距与操作控件；2560px 视口内容区约 1560px，3840px 约 2200px。
- API Key 维持双列，登录密钥维持三列；保持五个周期金额和顶部汇总在可读宽度内。
- 登录、设置、公告弹窗以及七天用量预览同步提升阅读尺寸。公告入口与收缩动画的尺寸保持一致。
- 兼容系统 125%、150%、200% 缩放及浏览器缩放，CSS 视口缩小时自然回落到较小布局。

备选：只加宽容器，改动少但文字依然偏小；增加大屏卡片列数，适合很多 Key，但少量 Key 时空白多，且需要改造七天预览行定位。

## 验证

用本地假数据检查 1920×1080、2560×1440、3840×2160 以及手机 390×844。检查内容宽度、横向溢出、金额截断、导航、登录与公告弹窗、七天预览左右展开及关闭后的布局恢复。执行项目全部测试、逐文件 JavaScript 语法检查与差异检查，保存桌面/手机截图。
