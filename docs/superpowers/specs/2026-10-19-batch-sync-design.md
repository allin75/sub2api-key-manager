# 全局批量同步与配额保存反馈

用户已在本会话确认方案并授权完成后发布 NAS，不再分阶段请求确认。

## 目标与边界

- 普通常规同步改为所有管理员每小时整点依次执行，共享本轮上游 Key 列表；保留北京时间 22:00–08:00 暂停及必要的月初、周重置、奖励到期、状态恢复任务。
- 上游 Key 列表仅驻留服务内存，按关联哈希筛选，不新增完整 Key 落盘或跨账号输出。列表有短时缓存，写入使其失效或更新对应项。
- 现有六周期/每日图表继续使用每日汇总；上游页面批量统计只有今日与总计字段，不用它替代自然月或体验/奖励记账，不增加冗余查询。
- 明细使用降序 ID 增量分页及已保存记录去重，重读交界页；旧版成功账本可作为增量基线。定期完整核对捕捉旧记录变化，失败不得将不完整账本当作成功或恢复 Key。首次导入/没有基线时完整扫描。
- 全部上游请求串行并有最小间隔；遇到 429 停止本轮后续读取，不立即重试。NAS 持久化全局冷却截止时间，取下一白天整点与 Retry-After 之后的可用时段，不因打开页面、手动刷新或重启绕过。
- 所有管理员缓存与轻量状态接口显示限流原因、最近成功时间和下一次尝试的北京时间，不把下次尝试说成保证成功。冷却时刷新按钮禁用，读页面不触发上游。
- 配额保存仅验证关联并写目标配额，确认后更新本地配额字段，不跑整批用量同步、不改用量更新时间。保存中禁重复提交，有等待反馈；成功、失败、保存后缓存异常分开提示。会话/管理员切换后的迟到响应不得污染新视图。

## 兼容性与验证

持久化字段均为可选增量字段，保留已有身份、归属、额度、奖励和公告。测试覆盖批量请求次数、列表身份校验、分页与迟到记录、跨月和重启、429 两种 Retry-After、夜间顺延、全局冷却、配额保存与失败/重复提交/会话切换。桌面和手机假数据验证保存反馈及限流提示，不改变卡片/预览定位。发布采用备份、候选镜像及失败回退，生产只做只读验收。
