# Sub2API 自定义 Key 用量管理

部署在 NAS Docker 中的内部管理页。它使用一个 Sub2API 普通账号读取 Key 名称和用量，但只展示、刷新和重置你手动加入管理列表的自定义 Key。

## 功能

- 保持单密码登录，不增加用户名。首次登录密钥默认 `111`（`ADMIN_PASSWORD`），只能查看、刷新及调整自己关联的 API Key 配额。
- 超级管理员密码默认 `superadmin`（`SUPERADMIN_PASSWORD`）：管理所有登录密钥、关联的 API Key 和各自的月度额度。
- 登录密钥可自行修改，超级管理员也可代改；新值不能与其他当前登录密钥或超级管理员密码重复。修改后旧密钥和该密钥的所有旧会话失效，需要重新登录。
- 改过才显示“曾用密钥”；超级管理员可按当前或曾用值搜索。曾用值只用于查找，不能作为登录别名。登录密钥区分大小写，首尾不允许空格。
- 超级管理员顶部显示登录密钥数量、月度总额度、月度已用/剩余、体验总额度及有效奖励余额；下方选择一条登录密钥，管理对应的 API Key 和用量。未设置额度的旧记录不会被算作零额度限制，用量未同步时不显示为零。
- 每条登录密钥有独立月度额度及账本，余额为该额度减本月实际消费。设定后立即计入关联 API Key 的当月已有消费，金额沿用到以后月份。
- 完整 Key 仅在添加时传给后端验证；磁盘只保存 SHA-256 哈希和脱敏值。
- 自动读取 Sub2API 中的真实 Key 名称、状态、累计额度和最后使用时间。
- 展示昨日、今日、本周、本月、上月的实际费用。
- 登录或恢复会话时，未确认当前版本公告的账号会收到强提醒，需点击“我已知晓”才能继续。确认记录随账号保存在服务端，换设备或修改登录密钥不重复提醒，新版本公告重新提醒。
- 确认后的公告平滑收缩至顶部导航栏，入口常驻，可随时重新查看；不再三天过期。导航栏整合公告、修改登录密钥和退出登录，适配手机。
- 公告弹窗只提供确认或收起操作，退出登录仅在顶部导航栏提供；右上角使用居中的 SVG 关闭图标。
- 登录支持入场、提交中反馈及进入管理页的顺序过渡；恢复已有会话不闪现登录表单。使用本地托管的 Anime.js 动画，尊重减少动态效果设置，脚本加载失败时仍可正常登录与确认。
- 悬浮 API Key 卡片可预览含今天的最近七天实际消费折线图，点击固定，再次点击、点击空白处或按 Esc 关闭。两列布局向外侧展开，空间不足时在卡片下方以浮层展开，不推动其他卡片；预览需在视口内上移时，会与卡片列留出间隙并用短线标明来源卡片。手机也支持点击查看，下方浮层不增加网格占位、不自动滚动页面；靠近视口边缘时调整浮层定位，内部内容可滚动。复用已有用量同步，旧缓存等待下次成功同步后显示每日明细。
- 月度账号的已同步余额低于或等于总额度 10% 时自动提醒，每个额度周期、每个账号提醒一次。登录或手动刷新时浏览器可能请求通知权限；授权后显示系统通知，HTTP 访问或未授权时改为页面内提醒。页面需保持打开；关闭浏览器后不会继续检查。
- 月度模式每周一 06:00（Asia/Shanghai）自动重置已配置自定义 Key 的累计额度和 5 小时/1 天/7 天限速窗口用量；体验模式不参与周重置。
- 页面显示距离下次自动重置的实时倒计时，不提供手动重置按钮。
- 支持单独调整已配置 Key 的额度上限，并展示累计用量进度条。
- 从页面移除 Key 只影响本地管理列表，不会删除 Sub2API 中的 Key。

## 在其他电脑继续开发

先阅读 [项目交接记录](docs/PROJECT_HANDOFF.md)。它记录当前源码与 NAS 部署状态、已完成工作和接手步骤；每次完成工作后随代码一同更新并推送。

```sh
git clone https://github.com/allin75/sub2api-key-manager.git
cd sub2api-key-manager
```

这是私有仓库，需要先登录有权限的 GitHub 账号。项目不包含生产环境的账号密码或 Key 数据。

使用 Node.js 22+（部署镜像使用 Node.js 24），无需安装 npm 依赖，浏览器动画脚本随仓库本地托管。复制 `.env.example` 为 `.env` 并填写配置后，可以运行：

```sh
node --test
node --env-file=.env src/server.js
```

本机开发时在 `.env` 添加 `DATA_DIR=./data` 和 `PORT=3100`，然后访问 `http://localhost:3100`。本地数据与 NAS 数据独立。

修改完成后提交、推送代码；GitHub 推送不会自动部署 NAS。更新 NAS 时保留原 `.env` 和 Docker 数据卷，勿使用模板覆盖已有配置。

### 管理员卡片定向公告

超级管理员点击某张登录密钥卡片的“发布公告”，填写标题和正文，仅发送给该卡片对应的管理员，不需要勾选接收人或进入独立管理页面。同一弹窗下方可以查看该账号的历史公告、待确认/已知晓状态与确认时间，二次确认后手动删除。

接收人登录后需逐条点击“我已知晓”；确认仅结束强提醒，不删除公告。顶部“公告”入口可以随时查看自己的公告记录，普通管理员不能发布、删除或读取其他人的公告。已登录页面在可见时每 15 秒同步一次，回到页面时也检查新公告。公告长期保留、没有自动过期，账号修改登录密钥或更换浏览器不会丢失公告与确认记录。现有额度规则说明及其确认流程保持兼容，与定向公告分别保存。

标题最多 100 个字符、正文最多 4,000 个字符，支持换行，按纯文本展示。持久化根状态新增可选 `targetedNotices`，按稳定账号 ID 归属，预算、奖励及调度写入不会覆盖公告。所有修改操作沿用会话、CSRF、来源校验和独占写入队列，旧数据无需破坏性迁移。

- `GET /api/notices`：读取当前登录账号收到的公告，超级管理员不会继承当前管理账号的公告。
- `GET /api/access-keys/:id/notices`：超级管理员读取某张卡片的发布历史。
- `POST /api/access-keys/:id/notices`：超级管理员发布 `{ "title": "标题", "body": "正文" }`。
- `POST /api/notices/:id/acknowledge`：接收人确认自己的公告，重复确认不改写首次时间。
- `DELETE /api/access-keys/:id/notices/:noticeId`：超级管理员删除该账号的一条公告。

本地假数据截图在 `docs/screenshots/2026-09-30-targeted-notice-*.png`。定向公告已随 `v1.2.0` 发布并部署 NAS，实际部署提交、验证与备份路径见 [项目交接记录](docs/PROJECT_HANDOFF.md)。

### 公告与动画

公告版本和分项内容定义在 `src/announcement.js`。发布需要重新确认的新公告时，同时更新 `version` 和内容；不要仅修改文案而保留旧版本号。普通账号按稳定 ID 保存确认，超级管理员单独记录，与其当前选择管理的账号无关。

`POST /api/announcement/acknowledge` 要求已登录会话、CSRF 验证和当前公告版本；重复确认不改写首次确认时间，写入失败保留弹窗并允许重试。旧浏览器的公告关闭记录不再参与判断。

Anime.js 4.5.0 的未修改浏览器发行文件和 MIT 许可证位于 `public/vendor/`，无运行时 CDN 请求，不放宽内容安全策略。公告到导航栏的布局过渡只在临时动画层内执行，不参与整页布局；退出或会话过期会清理未结束的动画。

页面根元素持续保留滚动条占位，公告打开时仍锁定背景滚动，关闭时恢复滚动；开关及收缩过程不改变页面宽度，避免左右晃动。手机使用覆盖式滚动条时不会额外占位。

公告卡片收缩到顶部后，入口图标和文字以 180 毫秒淡入并轻微放大，不再突然切换显示。动画层内关闭按钮的通用 CSS 过渡，避免与动画库叠加；减少动画模式和动画库不可用时直接展示入口，退出时清理临时样式。

收起时遮罩淡出结束后保持透明，直到布局过渡全部完成再隐藏并清理样式，避免末段重置遮罩导致闪屏；取消动画时仍恢复原始样式。

### 月度限额与调度

月度预算按登录密钥独立保存在本应用数据卷，使用 `actual_cost` 历史统计；单 Key 配额仍写入 Sub2API 的 `quota`。月度用量不会被周重置清零。金额以 USD 计，月周期固定北京时间，未用余额不结转。

超级管理员可在每张账号卡片独立设置“周刷新”和“月刷新”。旧月度账号默认均开启；一次性体验账号两项关闭且不可开启，需要先将额度类型切换为月度。

- 周刷新：每周一 06:00（北京时间）重置关联 API Key 的累计用量及限速窗口；不清零账号总额度的已用量。关闭后停止周重置及未完成的重试，重新开启从下一次周一 06:00 起生效。
- 月刷新：每月 1 日 00:00（北京时间）刷新账号总额度。关闭时不改变当前余额，以后持续累计已用量；重新开启不立即清零，从下一个月 1 日起刷新。关闭期间不会因月初而恢复已停用的 Key。
- 开关不会重置奖励记录或奖励期限，也不会立即恢复 Key。暂停月刷新后，尚未刷新的跨月用量与普通月度账本口径不同，此时暂不能转移 API Key 关联；重新开启并完成月刷新后可继续转移。

达到某条登录密钥的月度总额度后，应用只把它关联且启用的 API Key 改为 `inactive`，不影响其他登录密钥。每月 1 日 00:00 或提高总额度后余额大于零时，只恢复本应用因月度额度停用的 Key；原本禁用的 Key 不恢复。移除 Key 时保留当月消费快照及自动恢复记录，重加按同一个 Key 哈希计费，不重复累计。

一个 API Key 只能关联一条登录密钥。超级管理员可通过 Key 卡片上的“转移关联”调整归属，本月用量和自动停用恢复记录一并转移，按目标月度额度重新计算；转移前同步失败则保留原关联。归属保存后的同步失败会返回 `pendingSync: true`，页面提示“关联已转移，额度状态待同步”，后端继续重试。普通“移除”不会释放归属或退回本月已用额度。

| 北京时间 | 自动消费查询 |
| --- | --- |
| 每天 08:00–22:00 | 每小时，管理员卡片错峰 |
| 22:00–08:00 | 暂停 |

月初恢复、配置变更检查、状态变更失败重试和原有周一 06:00 重置不受夜间暂停限制。操作失败最快每 5 分钟重试；重启后继续，错过月初会补做。月度停用时跳过周重置，防止重新激活。

前三位管理员分别在每小时 :00 / :10 / :20 同步各自关联的 Key；时隙编号持久化，拖动排序不改变安排，重启后等待各自下一时隙，不集中刷新。六位以内间隔十分钟，超过六位在一小时内均匀分摊。接近 95% 用量也维持每小时正常查询。已验证的上游 Key ID 保存到配置中，后续直接查询目标 Key；旧数据首次匹配和新 Key 添加时才读取列表。

页面读取缓存，不直接访问上游；每条登录密钥的手动刷新最多 5 分钟一次，并合并同一密钥的并发刷新。所有登录密钥的消费查询、状态更新、配置修改和周重置共用串行队列。错误保留旧数据，不会当作零消费恢复 Key。页面显示“数据刷新于”最后成功时间；可见页面每五秒读取轻量同步状态，实际同步时显示提示和按钮内横向动画，不为读取缓存播放刷新动画。同步记录按账号保存最近 200 条失败/恢复事件及安全错误类别，重启不丢失。配额保存成功而后续同步失败会明确提示暂时显示旧数据。夜间、每小时间隔和上游统计延迟可能造成超额，这不是请求链路上的实时硬限额。

所有状态保存在 `/data/state.json`。首次升级到多登录密钥版本时生成 `/data/state.json.v3-backup`，将原 API Key、额度、账本、缓存和重置记录完整归到 `ADMIN_PASSWORD` 对应的第一条登录密钥下；更早的 v2 数据仍会先生成 `.v2-backup`。之后修改 `.env` 的 `ADMIN_PASSWORD` 不会覆盖页面里保存的新密钥。备份/恢复时停止应用，完整保存该卷及 NAS `.env`，避免只恢复其中一部分；回退旧版本需配合恢复升级前的状态备份。

### 一次性体验、限时奖励与排序

- 原额度可以选“按月”或“一次性体验”。体验从启用时开始计入消费，不随月份或星期刷新；修改体验金额保留已用量。切换回月度后按当月实际消费减奖励计算；再次切换为体验会开启新的体验周期，仅超级管理员可操作。
- 奖励归属登录密钥，关联的多个 API Key 共用。同一时间只允许一笔有效奖励，设置金额及到期时间；有效期内优先消耗奖励，超出的部分计入原额度。例如原额度 `80/120`，奖励 `0/40`，消费 $30 后显示 `80/120` 和 `30/40`，再消费 $15 后显示 `85/120` 和 `40/40`。
- 奖励用完或到期后不能继续使用，历史已用记录保留。发奖励不提高上游 Key 配额，不清零任何上游用量，也不恢复已经禁用的 Key；后续轮询同样不会仅因奖励恢复 Key。原有月初刷新或管理员调整原额度仍按原规则处理。
- 奖励不占原额度，但仍计入 Sub2API 实际消费、账户余额和单 Key 累计用量。页面的昨日/本月等历史统计也包含奖励消费。
- 奖励按每笔消费发生时间结算，起始时间包含、到期时间不包含；按记录 ID 去重，迟到记录重算归属。到期检查不受夜间暂停限制。用量查询失败保留旧账本并重试，不能保证请求级实时拦截。
- 体验与奖励需要上游 `/api/v1/usage` 提供带 ID、时间和 `actual_cost` 的明细。本版保留精简明细并重读相关 Key 的追踪区间以处理迟到记录；每个 Key 最多 1,000 页、每页 100 条，超出或分页异常会标记同步失败，不将不完整结果当作零消费。高用量长期体验需要后续引入增量归档。
- 月度密钥转移 API Key 时，奖励记录保留在发放方，已抵扣消费不会在接收方重复收费，新消费只能使用接收方的奖励。涉及体验模式的转移暂不支持，避免混合月度与累计账本。
- 超级管理员可拖动登录密钥卡片的名称区域；每个登录密钥的 API Key 卡片可拖动名称或编号区域，普通登录只可调整自己的顺序。没有额外拖拽图标或上下按钮；支持触摸拖动，也可聚焦标题后按 Alt 加上下方向键排序。顺序保存在服务端，刷新或换设备后保留。搜索登录密钥时暂停排序；并发修改冲突会提示刷新重试。排序不会改变归属或默认管理范围。
- 子管理员没有奖励记录时隐藏整个临时奖励区域；超级管理员仍保留发放入口。

这些字段兼容旧数据，旧记录默认保持月度模式。升级前仍应备份完整数据卷；回退旧程序应恢复配套状态备份，避免忽略奖励抵扣。

### 接口

- `POST /api/login`、`GET /api/session` 返回 `role: admin | superadmin`。
- 普通会话额外返回自己的 `accessKey`（id、secret、previousSecrets），后端按固定 id 隔离全部数据。
- `GET /api/access-keys`：仅超级管理员，返回全部登录密钥、曾用值、API Key 数量及各自月度预算。
- `POST /api/access-keys`：仅超级管理员，提交 `{ "secret": "mise111", "limit": 100 }` 新增登录密钥。
- `PUT /api/access-keys/:id`：仅超级管理员，提交 `{ "secret": "new-secret" }` 代改登录密钥。
- `PUT /api/login-secret`：普通登录修改自己的登录密钥，提交 `{ "secret": "new-secret" }`。
- `GET /api/keys` 返回缓存的 `keys`、周重置 `schedule` 和月度 `budget`（limit、used、balance、overage、month、status、stale、error、lastSuccessAt、nextCheckAt、nextMonthAt）。
- `POST /api/refresh` 申请受全局节流约束的刷新；复用缓存时返回 `cached: true`。
- `GET /api/sync-status` 返回当前管理员的同步状态、最后成功时间及失败/恢复记录；不触发上游访问，普通管理员不能查询其他账号。
- `PUT /api/budget`：超级管理员提交 `{ "limit": 1000 }`，必须为正数，最少 $0.01。
- `PUT /api/refresh-policy?accessKeyId=...`：仅超级管理员，提交 `{ "weeklyResetEnabled": false, "monthlyResetEnabled": true }`，允许只传其中一个布尔开关。返回的 `budget` 和账号列表包含两个开关的有效状态；关闭的刷新不显示下次刷新时间。
- `POST /api/keys` 和 `DELETE /api/keys/:id`：仅超级管理员可用。
- `PUT /api/keys/:id`：调整单 Key 配额；月度停用/恢复尚未完成时返回 409。
- `POST /api/keys/:id/transfer`：仅超级管理员，提交 `{ "accessKeyId": "目标登录密钥 ID" }` 转移关联。
- 新建登录密钥和 `PUT /api/budget` 可传 `type: "monthly" | "trial"`；省略时分别默认月度/保留原类型。体验视图的 `schedule`、`nextMonthAt` 为 `null`。
- `POST /api/rewards`：仅超级管理员，提交 `{ "limit": 40, "expiresAt": "2026-10-01T00:00:00+08:00" }`。视图的 `rewards` 返回每笔奖励的已用、剩余、起止时间和状态。
- `PUT /api/access-keys/order`：仅超级管理员；`PUT /api/keys/order`：当前管理范围。提交 `{ "ids": ["完整有序 ID 列表"], "version": 0 }`，版本来自列表 `orderVersion`。列表不完整、重复或版本过期返回 409。

超级管理员为 `/api/keys`（含子路径）、`/api/refresh`、`/api/budget`、`/api/rewards` 添加 `?accessKeyId=...` 选择管理范围；省略时使用升级保留的默认登录密钥，不受排序影响。普通会话自动使用自身范围，指定其他范围返回 403。

所有写接口保留会话与 CSRF 校验。月度设置保存后同步失败时返回已保存设置和过期标记，后端继续按调度重试。

## NAS Docker 部署步骤

1. 将整个 `sub2api-key-manager` 文件夹上传到 NAS。
2. 在该目录复制环境变量模板：

   ```sh
   cp .env.example .env
   ```

3. 编辑 `.env`，至少填写：

   ```env
   ADMIN_PASSWORD=111
   SUPERADMIN_PASSWORD=superadmin
   SUB2API_BASE_URL=https://sub2api.yfyf.fun
   SUB2API_EMAIL=你的普通账号邮箱
   SUB2API_PASSWORD=你的普通账号密码
   ```

4. 构建并启动：

   ```sh
   docker compose up -d --build
   ```

5. 浏览器访问：

   ```text
   http://NAS地址:3100
   ```

6. 查看运行状态：

   ```sh
   docker compose ps
   docker compose logs --tail=100 key-manager
   ```

## HTTPS 反向代理

如果通过群晖、威联通、Nginx Proxy Manager 或 Caddy 提供 HTTPS，请将 `.env` 中的 `COOKIE_SECURE` 改为 `true`，然后执行：

```sh
docker compose up -d
```

反向代理目标为 `http://NAS地址:3100`。不要将 3100 端口直接暴露到公网。

## 数据与安全

- 持久化文件位于 Docker 命名卷 `sub2api-key-manager_key-manager-data` 中，不包含完整上游 API Key。为支持查看和按曾用值查找，管理页登录密钥及其历史值会明文保存在该卷中，文件权限为 `0600`；普通登录只能读取自己的值，超级管理员可以读取全部值。
- Sub2API 邮箱和密码位于 `.env`。限制该文件的读取权限，并不要把它提交到 Git。
- `ADMIN_PASSWORD` 只用于首次初始化。后续在页面修改登录密钥；超级管理员密码仍通过 `SUPERADMIN_PASSWORD` 配置并重启生效，不能与现有登录密钥重复。
- 管理会话在容器内存中保存 12 小时；容器重启后需要重新登录。
- 当前自动登录不支持启用了二步验证的 Sub2API 账号。

## “重置”的准确含义

应用会对每个已配置自定义 Key 调用：

```http
PUT /api/v1/keys/{id}

{
  "reset_quota": true,
  "reset_rate_limit_usage": true
}
```

它会重置 Key 的累计已用额度以及限速窗口用量，但不会删除 Sub2API 中已有的历史用量日志，因此昨日、本月等历史统计仍会保留。
